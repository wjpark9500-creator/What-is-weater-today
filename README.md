# 오늘, 창문 열까? — 출근 환기 판정 앱

`출근_환기_판정기준.json` 의 규칙을 그대로 구현한 정적 웹앱입니다.
기온/습도/강수는 기상청 초단기실황, 미세먼지는 에어코리아 데이터를 사용합니다.

## 파일 구성
```
index.html      메인 페이지
style.css       디자인
app.js          GPS/지역선택 + API 호출
api/verdict.js  Vercel 서버리스 함수 (API 키를 서버에서만 사용, 판정 로직 포함)
```

## 배포 방법 (냉장고 프로젝트와 동일한 흐름)

1. 이 폴더를 GitHub 새 저장소에 push 합니다.
2. Vercel에서 **New Project → 방금 만든 저장소 선택**.
   - Framework Preset: **Other** (정적 프로젝트라 자동 감지되면 그대로 둬도 됩니다)
   - Root Directory: 저장소 최상위 (별도 폴더 없음)
3. **배포 전에** Vercel 프로젝트 설정 → **Environment Variables** 에서 아래 두 개를 등록합니다.
   - `KMA_API_KEY` : 기상청 초단기실황조회 서비스의 **Decoding** 인증키
   - `AIRKOREA_API_KEY` : 에어코리아 대기오염정보 서비스의 **Decoding** 인증키
   - (환경변수 등록 후에는 Redeploy 한 번 해줘야 반영됩니다)
4. Deploy.

## 로컬에서 테스트하려면
Vercel CLI로 서버리스 함수까지 함께 띄워야 GPS/판정이 동작합니다.
```
npm i -g vercel
vercel dev
```
`.env` 파일을 만들어 아래처럼 넣어두면 `vercel dev` 가 읽어줍니다.
```
KMA_API_KEY=발급받은_디코딩_키
AIRKOREA_API_KEY=발급받은_디코딩_키
```

## 판정 로직 우선순위 (원본 기준 문서 그대로)
1. 미세먼지/초미세먼지 나쁨 이상 → 창문 닫기
2. 강한 비 / 빗물 유입 가능 → 창문 닫기
3. 공기질 좋음 + 강수 없음 + 기온 18~27℃ + 습도 40~60% → 활짝 열기
4. 공기질 좋음 + (기온 27~30℃ 또는 습도 60~70%) → 10~20분 환기 후 닫기
5. 공기질 좋음 + (기온 30℃ 초과 또는 습도 70% 초과) → 5~15분만 환기 후 닫기
6. 공기질 보통 → 10~20분 환기 후 닫기
7. 데이터 애매/누락 → 10~20분 환기 권장 (fallback)

## 참고
- 미세먼지 등급 기준은 환경부 기준(PM10 나쁨 81㎍/㎥↑, PM2.5 나쁨 36㎍/㎥↑)을 사용했습니다.
- GPS 좌표 → 시/도 이름 변환에는 무료 Nominatim(OpenStreetMap) 역지오코딩을 사용합니다. 별도 키가 필요 없습니다.
- 공공데이터포털 API는 하루 호출 한도가 있지만(서비스마다 보통 1,000회/일), 개인이 아침마다 확인하는 용도로는 충분합니다.
